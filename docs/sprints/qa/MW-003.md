## Observações (não bloqueiam)

1. **Sem verificação manual da API nesta rodada.** O SDK .NET não está nesta sessão, então não
   subi a API nem chamei com `curl`. A evidência da API vem só do CI e da leitura do código.
2. **Formato do número em JSON varia com a escala do `decimal`.** O total vem como `0` quando não
   há gastos, como `0.30` e `158.40` quando há (o .NET preserva as casas). Para o front não faz
   diferença, mas um cliente que compare strings vê formatos diferentes. Isso combina com a MW-009
   (2 casas fixas), que hoje fala só de `amount`. Vale o PO incluir o `total` nela.
3. **Falta um teste de "POST inválido não altera o total".** Hoje isso é garantido pela validação
   da MW-001, mas nenhum teste do total exercita o caso.
4. **Resposta malformada no front.** Se a API devolver `{}` ou `{"total": null}` com 200,
   `formatBrl(undefined)` mostraria "R$ NaN". É improvável com a API atual, então fica só o
   registro.
5. **Fuso horário servidor x navegador:** segue fora de escopo, como diz a história. Nos testes, o
   `FixedTimeProvider` usa UTC.
