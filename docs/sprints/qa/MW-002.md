## Casos de borda verificados

| Caso | Resultado |
|---|---|
| Valor negativo / zero / descrição vazia no POST | 400, e nada entra na lista (regressão da MW-001 ok) |
| Mesmo mês de outro ano (`2025-11-10`) | Não aparece. O filtro é por intervalo de datas completo, não só pelo mês |
| Query string inesperada (`?month=2026-10`) | Ignorada, devolve o mês atual (sem filtro por mês, como manda o "fora de escopo") |
| `DELETE /api/expenses` | 405 (não há exclusão, MW-005) |
| `GET /api/expenses/<id>` | 404 (o `Location` do 201 continua apontando para uma rota que não existe, já era assim na MW-001) |

## Observações (para o PO)

1. **"Hoje" do servidor e "hoje" do navegador podem divergir.** A API calcula o mês atual pela
   data local do servidor, e o front envia a data local do navegador (decisão da MW-001). Se os
   fusos forem diferentes, perto da virada do mês um gasto registrado com "hoje" no navegador pode
   cair em outro mês para a API e não aparecer na lista. Em uso local (mesma máquina) isso não
   acontece. Vale considerar quando houver deploy.
2. **Nenhum teste fixa "hoje" perto da virada do mês ou do dia** (ex.: 30/11 às 23h30 em -03). O
   `FixedTimeProvider` dos testes usa UTC ao meio-dia. O cálculo foi verificado só por leitura.
3. **Débito técnico do `launchSettings.json` foi resolvido** no commit `2ecb88c` (`chore:` separado,
   como pede o backlog), mas o item continua listado em "Débitos técnicos" no `BACKLOG.md`. O Tech
   Writer/PO deve remover.
4. Valor sem casas fixas na resposta (`"amount":5` em vez de `5.00`) continua igual à MW-001. Já
   está registrado na MW-009. O front formata corretamente (`R$ 5,00`).
5. O front mostra "Carregando…" enquanto a primeira carga não termina. Não está nos critérios, mas
   evita mostrar "Nenhum gasto..." antes da hora. Não bloqueia.
6. `categoryLabel` devolve o código cru (ex.: `food`) se a API mandar uma categoria desconhecida. Hoje
   isso não acontece, porque a API valida a categoria.
7. Depois de um erro ao recarregar, a lista que já estava na tela é trocada pela mensagem de erro.
   Isso está de acordo com o critério 12, que pede a mensagem "no lugar da lista".
