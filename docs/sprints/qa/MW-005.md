## Observações (não bloqueiam)

- **Critério 8 pendente:** `docs/api.md` precisa de `PUT /api/expenses/{id}` (exemplo de requisição, 200, 400 com as mensagens, 404) e `DELETE /api/expenses/{id}` (204, 404). Tech Writer. Vale mencionar que um id que não é Guid também dá 404 e que, sem `date`, a edição usa a data de hoje.
- **Mensagem de erro de exclusão não some sozinha:** `deleteFailed` só volta a `false` na próxima tentativa de excluir. Passos: excluir com a API fora → aparece "Não foi possível excluir o gasto." → registrar ou editar outro gasto com sucesso (a lista recarrega) → a mensagem de erro antiga continua na tela. Não fere o critério 15, mas é feedback velho.
- **Excluir o gasto que está em edição:** clicar "Editar" num gasto e depois "Excluir" nele mesmo deixa o formulário em "Editar gasto" de um gasto que não existe mais; ao salvar, a API dá 404 e aparece "Não foi possível salvar as alterações." até a pessoa clicar "Cancelar". Comportamento coerente com o critério 12, mas confuso. Sugestão para o PO: ao excluir o gasto em edição, voltar o formulário a "Novo gasto".
- **Duplo clique em "Excluir":** enquanto o DELETE não volta e a lista não recarrega, o botão continua ativo; um segundo clique confirmado manda outro DELETE, que dá 404 e mostra "Não foi possível excluir o gasto." mesmo com o gasto já excluído. Raro, cosmético.
- **Valor "45,90" no campo:** o campo de valor é `type="number"`, então mostra `45.9` (ou `45,9`, conforme o idioma do navegador), não `45,90`. O teste confere o valor numérico. É o mesmo campo da criação; se o PO quer as 2 casas na edição, é ajuste de apresentação.
- **Data apagada na edição:** se a pessoa limpar o campo de data e salvar, o front não envia `date` e a API grava a data de hoje (mesma regra da criação, registrada nas decisões do Dev). Na edição isso pode mudar a data de um gasto antigo sem a pessoa perceber. Candidato à MW-009.
- **Rolagem no celular:** "Editar" fica na lista, no fim da página; o formulário que muda fica no topo. Sem rolagem automática, no celular a pessoa pode não ver que entrou em modo de edição.
- **Tamanho do PR:** cerca de 300 linhas de produção e 530 de teste. O limite de ~300 da história fala de PR revisável; a produção ficou no limite. Fica para o revisor e o PO.
- Não houve teste manual com `curl` por falta do SDK .NET nesta sessão; a evidência da API é o CI no mesmo head.
